# 演示步骤与面试讲解

## 五分钟演示

1. 展示项目首页，说明模拟数据和上游来源。
2. 使用分析员账号登录，展示授权店铺的六个月销售趋势。
3. 输入“比较上个月各品类的销售额和订单退款率”，参考日期选 `2026-11-13`。
4. 展示指标定义、分析计划、SQL 和结果表，解释支付队列退款率与期间退款金额的区别。
5. 打开报告，逐项回到查询依据，展示观察结果与待验证推断。
6. 刷新页面，进入历史任务，展示结果可恢复。
7. 演示取消和重试，说明任务终态竞争与取消传播。
8. 切换管理员，展示用户店铺授权与项目预算。

## 面试回答线索

### 为什么选择这个场景

电商指标需要同时处理业务定义、时间范围、多表关联及权限边界。自然语言入口可以改善查询体验，SQL 和证据保留则支持人工复核。

### 如何处理模型生成的 SQL

从授权 Schema 和指标上下文生成计划，限定工具类型，使用 Druid AST 检查表与函数引用，再用对应店铺账号执行。数据库视图继续执行店铺过滤，结果与实际执行 SQL 一起保存。

### 如何避免 JOIN 导致指标错误

退款明细会导致订单金额被重复累计，因此退款使用 EXISTS 或先聚合。针对评测中发现的 LEFT JOIN 日期过滤错误，增加结构检查与回归用例。固定问题仍与独立标准 SQL 核对。

### 如何处理取消和断线

任务由后端队列拥有，SSE 负责读取进度。取消先争取数据库终态，再取消模型 Future 和 JDBC Statement。完成、取消和超时使用条件更新，只有一个终态生效。

### 哪些能力来自上游

Graph 框架、Spring AI 模型调用基础、通用数据分析代码、Nuxt 工程、结果表格组件和 ECharts renderer 均有明确上游来源。电商入口、业务词典、授权视图、任务生命周期及评测属于本项目的业务改造。
